# Security Advisory: SEC-2026-01

**Title:** Control-plane authorization gap in zn management API  
**Date:** 2026-09-07  
**Severity:** High (CVSS: 8.8 / CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H)  
**Vulnerability Type:** Broken Object Level Authorization (BOLA) / Missing Function Level Access Control (CWE-285 / CWE-862)  
**Remediation Commit:** `6ebce2f`  
**Reported by:** [WinstonRedGuard (github.com/WRG-11)](https://github.com/WRG-11)  

---

### Summary

A vulnerability was identified in the management HTTP API of `zn` where control-plane handlers under `/api/v1/policies*` and `/api/v1/consensus*` validated incoming API keys through `api_key_auth` middleware, but omitted function-level role authorization checks. As a result, an authenticated non-admin tenant could execute privileged control-plane operations, such as uploading, updating, or deleting platform policies, or registering consensus witness signatures without holding the `SuperAdmin` role.

---

### Affected Endpoints

* `GET /api/v1/policies`
* `POST /api/v1/policies/upload`
* `POST /api/v1/policies/delete`
* `GET /api/v1/consensus/pending`
* `POST /api/v1/consensus/sign`
* `POST /api/v1/consensus/deny`

---

### Impact

An attacker with valid API credentials for any regular tenant could:
1. Modify, upload, or delete active security policies, potentially weakening security guards or altering prompt injection detection behavior.
2. Intervene in multi-party consensus decisions by signing or denying pending state changes without required administrative rights.

---

### Remediation

The issue was remediated in commit `6ebce2f` with the following changes:
1. **Strict Role Verification:** Handlers across all policy and consensus management routes now require `Extension(tenant): Extension<TenantContext>` and strictly enforce `tenant.role == TenantRole::SuperAdmin`.
2. **Witness Caller Validation:** In `consensus_sign_handler`, the handler explicitly verifies that the caller possesses `SuperAdmin` authorization before accepting the witness signature.
3. **Automated Regression Tests:** Added integration tests verifying that non-superadmin authenticated callers receive HTTP 403 Forbidden on all affected endpoints.
